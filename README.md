# Орден — приложение (ПК и Android)

## Что это и как связано

Сайт, ПК-приложение и Android-приложение = **одно приложение, три окна**.
Все читают и пишут в одну базу Firebase Firestore. Поэтому:

- участник, который зашёл через сайт, **видит** сообщения из приложения и наоборот;
- сообщение, написанное на одном устройстве, приходит на остальные **сразу** (это делает сам Firebase, без вашего участия);
- уведомление, когда приложение закрыто, приходит через **push** (Android — FCM, браузер и ПК — Web Push, его отправляет `functions/index.js`).

Обновление: в корне сайта лежит `version.json` с номером версии. Сайт и приложения
сравнивают его со своей версией и показывают баннер «Обновить». Нажали — страница
перезагрузилась на новой версии. **Переустанавливать приложения не нужно.**

## Шаг 1. Выложить сайт (5 минут)

1. Откройте репозиторий на GitHub, в котором лежит сайт.
2. Замените файлы: `index.html`, `sw.js`, `manifest.json`, `firestore.rules`.
3. Добавьте новые файлы: `version.json`, `firebase-messaging-sw.js`.
4. **Повышайте номер версии при каждой правке сайта**: в `version.json` замените `1.0.0` на `1.0.1`
   и т. д. Это единственное, что заставляет приложения показать «Обновить».
5. Commit changes.

Через 1–2 минуты GitHub Pages обновит сайт. Обновите страницу — версия новая.

---

## Шаг 2. Правила Firestore (2 минуты)

В Firebase Console → Firestore → вкладка **Rules** → вставьте содержимое `firestore.rules` → **Publish**.

Новые коллекции, которые появляются в правилах:

- `pushtok/{uid}` — подписки на push у браузера;
- `devtok/{uid}` — токены Android-устройств;
- `config/{id}` — публичные ключи от сервера (например, ключ Web Push).

Старое поведение не сломается: чужое правило не трогает остальные коллекции.

## Шаг 3. Уведомления сайта и ПК (Web Push)

1. Сгенерируйте ключи Web Push (выполните в терминале на компьютере):

   ```
   npx web-push generate-vapid-keys
   ```

   Получите две строки: `Public Key` и `Private Key`.

2. Запишите публичный ключ в базу: Firestore → `config` → документ `push` → поле `key` = публичный ключ.
   (Поле `key` читают все, а записать может только владелец.)

3. Установите Cloud Functions (уже один раз пробовали, понадобится Blaze):

   ```
   npm i -g firebase-tools
   firebase login
   firebase use orden-carstvie
   cd functions
   npm install
   cd ..
   firebase functions:secrets:set VAPID
   ```

   На вопрос среды вставьте строку:

   ```
   {"public":"<ваш публичный ключ>","private":"<ваш приватный ключ>"}
   ```

   Затем:

   ```
   firebase deploy --only functions
   ```

4. В `functions/package.json` добавьте пакет: в разделе зависимостей должна быть строка
   `"web-push": "^3.6.7"` (это уже нужно, файл `package.json` я не менял, поэтому впишите `npm install web-push --prefix functions` перед деплоем).

> Ограничение: **бесплатно** push при **полностью закрытом** сайте не работают — Cloud Functions требуют Blaze.
> На Blaze есть бесплатный объём — как правило, для маленького сообщества он покрывает работу.
> Уведомления при свёрнутой вкладке, из уже закэшированного сайта, работают и без Functions.

## Шаг 4. Android-приложение (APK)

### Что нужно поставить на компьютер с Windows

1. **JDK 17** (Temurin) — для сборки.
2. **Android Studio** — самый простой способ, там уже есть SDK и эмулятор.

### Подключить Firebase к Android

1. Firebase Console → правый верхний значок → **Project settings** → **Your apps** → **Добавить приложение (Android)**.
2. Package name: `ru.orden.app`.
3. Скачайте `google-services.json`, положите в `android/app/google-services.json`.
4. Скопируйте `cloudmessaging` ключ от сервера: Firebase Console → Project settings → **Cloud Messaging** → `VAPID key` — не нужен для Android; для Android достаточно `google-services.json`.

### Сборка

1. Откройте **Android Studio** → **Open** → выберите папку `android/`.
2. Дождитесь Gradle Sync (может качать 2–5 минут).
3. Меню **Build** → **Build App Bundle(s) / APK(s)** → **Build APK(s)**.
4. Адрес готового файла появится в уведомлении: `android/app/build/outputs/apk/debug/app-debug.apk`.
5. Скопируйте APK на телефон и установите (на телефоне надо разрешить «Установка из неизвестных источников»).

Подпись для Google Play делается там же: Build → Generate Signed Bundle → APK.

> Отладка на реальном телефоне: включите **USD-отладку** (Developer options) и подключите кабель.
> Или сразу установить `app-debug.apk` руками — для 10–20 человек этого достаточно.

### Что уже настроено в приложении

- WebView-оболочка загружает ваш сайт: первая страница — сайт, а всё меню, чат, роли — внутри.
- `PushService` принимает FCM-сообщения, когда приложение закрыто, и показывает уведомление.
- Нажатие на уведомление открывает тот же сайт.
- Микрофон разрешён для голосовых; выбор фото — через системное окно.
- Кнопка «Обновить» при появлении новой версии.

## Шаг 5. ПК-приложение (Electron)

Нужен Node.js 20. В терминале в папке `desktop/`:

```
npm install
npm start               # запустить для проверки
npm run dist            # собрать установщик Windows
```

Готовый установщик: `desktop/dist/Orden-Setup-1.0.0.exe`.

Внутри ПК-приложения:

- грузится **тот же** сайт;
- без интернета — из сохранённой копии (`desktop/stage/index.html`);
- раз в 15 минут проверяет `version.json` и показывает баннер «Обновить».

Если хотите «чтобы ПК-приложение обновлялось само» (без скачивания установщика):
поставьте `electron-updater` на GitHub Releases — я опишу, но для 10 человек это не обязательно.

## Что изменилось в коде сайта (только добавления)

В `index.html` после `const FB={...}`:

```js
var APP_VER="0.0.0",APP_VER_LIVE="",_UPD=null;
```

Добавлены 5 новых функций перед `function modal(html)`:

- `verCheck()` — спрашивает `version.json`, сравнивает;
- `showUpd()` — показывает баннер;
- `applyUpd()` — перезагружает сайт с новой версией;
- `boot()` — регистрирует `sw.js`, запускает проверки и `pushInit()`;
- `pushInit()` — подписывает устройство на Web Push.

Старые функции **не переписаны**, поэтому чат, роли, звонки и всё прочее работает как раньше.

## Ограничения, про которые честно

- **Push при полностью закрытом сайте** на GitHub Pages с Firebase — только через Cloud Functions
  (тариф Blaze с привязкой карты, но небольшой бесплатный объём). Без него уведомления
  приходят, когда вкладка свёрнута, но не когда сайт полностью закрыт.
- **Push на Android-приложении** работают и без Cloud Functions, если Firebase подключён:
  это делает приложение (FCM), а не сайт.
- Firebase — сервис Google. В части регионов и у некоторых операторов доступ может быть
  нестабильным. Это свойство сети, а не приложения.
- Публикация APK в Google Play требует отдельной регистрации разработчика. Для своих читателей
  достаточно установки APK вручную или через Google Drive.
- **Пароли**: в чате раньше появлялись пароли от почты — смените их, если ещё не сделали.
